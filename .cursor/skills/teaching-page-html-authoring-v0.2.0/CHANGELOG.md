# ChangeLog

## teaching-page-html-authoring v0.2.0（2026-07-23）

新增 `experience-design.md`，把体验命题、教学视觉主角、互动原型、教学可视化、状态叙事、素材策略和响应策略设为生成前的显式设计输入。

增强单页 HTML 的工程与体验合同：核心数据使用单一状态源，学科答案与非法操作先在数据层校验，核心操作形成“输入或操作—状态变化—可见反馈”的闭环；自包含任务使用内联 SVG、Canvas 或 CSS，不把远程地址当作内联素材；写入前检查 JavaScript 字符串、DOM 引用、单页壳状态和资源闭合。

补齐桌面与小屏的视口几何约束。内容盒、Grid/Flex 子项和绝对定位装饰不得扩大文档宽度，教学主图在 1440px 与 390px 视口下都要保留完整语义边界、关键节点和关系路径。

清理开发包元数据：Skill 根目录使用稳定 ID `teaching-page-html-authoring`，`SKILL.md` frontmatter 仅保留 `name` 与 `description`，移除环境、实验和临时版本字段。正式版本由目录名、发布包名与 Notion 版本记录共同管理。

验证：Skill 结构校验通过；整理前的同内容组合在四类单页场景的八次生成中完成 8/8 产物回收、8/8 动态工程验收，并通过工程与质量门槛。开发版的职责去重不改变 Skill 内的单页合同，但与 Runner SP v0.3.0 的组合仍需再做一次正式回归。

## education-content-runner-system-prompt v0.3.0（2026-07-23）

新增生成任务执行优先级：主 Skill 已完整读取且不存在真实阻塞时，必须继续推进到产物写入，不能用分析、计划或文件读取记录代替交付。

新增固定运行时代码注入边界：当 Skill 明确规定由写入工具注入固定源码时，模型遵循占位合同，最终以写入工具回读后的完整产物为证据；注入失败、占位符残留或无法回读时保持能力阻塞。

新增跨 Skill 最小预检，同时收紧职责边界。Runner 只检查输入、流程与写入合同是否闭合；学科正确性、资源策略、代码闭合、交互状态、页面几何和具体产物格式继续由主 Skill 持有，避免在 System Prompt 中复制一套 HTML 实现规则。

验证：文档结构与职责边界完成静态检查。由于本次把重复的单页细则归回 Skill，v0.3.0 状态为“验证中”，不自动替换当前使用版本。
