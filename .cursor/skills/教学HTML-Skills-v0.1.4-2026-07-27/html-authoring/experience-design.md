# 单页教学体验设计层

本文件位于需求契约和 HTML 实现之间。它的作用是先确定学生实际经历什么，再进入通用或数学链路选择色板、布局和组件。不要把色板、卡片、阴影、图片数量或代码体积当成体验设计；视觉复杂度只有转化为更清楚的教学对象、因果关系、进度与反馈时才有价值。

## 1. 先写体验命题

用一句话写清本页的体验命题：

```text
学生通过 <关键动作> 操作/观察 <教学视觉主角>，从 <初始认知> 走到 <可验证理解或完成状态>。
```

体验命题必须落到页面中的对象和状态。诸如“现代、活泼、科技感、沉浸式”只能是表现补充，不能替代关键动作、视觉主角和完成状态。

## 2. 选择一个主原型

只选一个主原型，其他原型只能作为局部能力。主原型决定首屏重心和状态节奏：

| 原型 | 首屏视觉主角 | 必须看得见的状态变化 |
|---|---|---|
| `simulation` 模拟探索 | 与参数因果绑定的场景、图形或模型 | 参数变化 → 主体变化 → 数值/解释同步 → 重置 |
| `game-challenge` 闯关游戏 | 当前关卡与可操作题面，而不是规则卡片 | 开始 → 当前目标 → 判定/奖励 → 进度 → 结算/再玩 |
| `visual-explanation` 可视化讲解 | 能承载概念关系的图解、流程或操作模型 | 逐步揭示/比较 → 关键关系高亮 → 归纳 |
| `guided-practice` 引导练习 | 当前题目、作答对象和反馈 | 作答 → 解释性反馈 → 重试/下一题 → 完成 |
| `interactive-poster` 互动海报 | 一幅完整的语义主图 | 热点/阶段切换 → 就近解释 → 全局关系保持可见 |
| `print-material` 打印材料 | 题区、图解或阅读结构 | 屏幕辅助控件与打印态内容分离 |

如果用户同时要求“讲解 + 闯关 + 海报”，按学生主要投入时间的动作选择主原型，并把其他要求放进开始引导、局部关卡或总结，不要把三套页面骨架平铺在同一首屏。

## 3. 定义教学视觉主角

每页只保留一个视觉主角。它应占据主体区域的大部分有效注意力，桌面首屏通常给它约 55%–75% 的主内容空间；规则、提示和统计压缩为支持层，不能用等权卡片把主角切碎。视觉主角满足至少一项：

- 表达数量、空间、时间、因果、组成或流程关系；
- 能被学生操作，且操作会改变可观察状态；
- 在解释、反馈和总结中被重复引用；
- 删除它会显著降低理解，而不只是降低美观。

主角可以是 SVG/Canvas 场景、分步流程、面积或长度模型、数轴、关系图、地图、时间线、实验装置、可操作卡组。优先用自包含的 SVG/CSS/Canvas 建立前景对象、中层关系、背景环境和就近标注，让复杂度体现在可读关系与空间层次上。卡片网格、通用插图、装饰背景和大标题通常不是教学视觉主角。

抽象知识优先选择能保留结构关系的表示：数量关系用长度、面积、集合或数轴；过程关系用流向、阶段和物质/能量变化；物理因果用位置、方向、向量、轨迹或实时读数；分类与网络关系用可追踪的节点、连线和局部高亮。表示必须与真实数据和判定逻辑共享同一状态，禁止图解只是静态装饰。

## 4. 写教学可视化合同

在编码前完成三列映射：

| 教学关系 | 视觉编码 | 与交互/反馈的绑定 |
|---|---|---|
| 学生需要理解的关系 | 用位置、长度、面积、方向、颜色或连接中的哪一项表达 | 哪个动作改变它，反馈如何引用它 |

至少有一个核心关系必须完成这三列。颜色只承担稳定语义，例如“原料/产物”“已完成/待完成”“两组数量”，不要为了使用更多色板颜色而给同一概念随机换色。涉及数学、图表或物理关系时，所有视觉元素必须来自同一数据模型和坐标变换。

## 5. 设计状态叙事

先写状态，再写组件。状态至少覆盖：

```text
initial       首次进入时，任务和第一动作是否一眼可见
engaged       学生操作后，视觉主角和数据如何同步变化
feedback      正确、错误或未达成时，哪里解释原因与下一步
completion    完成后，如何呈现结果、阶段感与继续/再玩入口
reset         是否恢复数据、视觉主角、反馈与焦点
mobile        375–390px 下保留哪些核心对象，哪些信息折叠或后置
```

`game-challenge` 需要让开始页、关卡页、反馈页和结算页具有可辨识的状态差异；仅有“第 2/5 题”文字不构成闯关体验。即使用户要求独立开始页，首屏也不能退化成大面积空白里的标题、说明和单按钮：应让任务路线、关卡节点、核心题型预览或与知识点绑定的操作教具成为可见主角，并让开始按钮紧邻它。`simulation` 需要保留一个稳定舞台，不能让每次反馈把主体顶走。`interactive-poster` 的局部解释应靠近被点击对象，同时保持全局关系可回看。

## 6. 形成一套艺术方向

艺术方向由“受众 + 学科隐喻 + 视觉主角 + 状态节奏”共同决定。写出一个可以约束实现的短句，例如“观察站仪表 + 清晰矢量标注”“桌面教具 + 可拼装数量块”“任务地图 + 能量式进度”。随后统一：

- 形状语言：几何、手作、仪表、地图、实验台或纸面教具；
- 线条与图标：同一笔触、同一箭头和标注系统；
- 空间隐喻：舞台、工作台、路线、实验台或挑战地图；
- 动效语义：只强化因果、步骤、反馈和完成，不做持续干扰动画；
- 色彩角色：背景、主体、动作、反馈、警告各有稳定职责。

现有学科色板是颜色来源，不是艺术方向。不要因为命中色板就默认生成“标题 + 卡片 + 右侧控件”的通用工具页；布局应先服务视觉主角和主原型，再在学科链路允许的变体中落地。至少加入一种与主题绑定的材质或空间隐喻，例如实验台、流域剖面、机械装置、纸面教具或任务路线；装饰层不得与教学数据争抢注意力。

## 7. 素材策略

图片数量不构成目标或限制。只有当真实图片能提供 CSS/SVG 难以替代的情境、人物、地点、自然质感或观察细节，且用户没有要求自包含或禁止外部资源时，才考虑图片生成；调用前须读取同 skill 的 `references/image-generation.md`，工具名为 `generate_image`。图解、流程、数学关系、实验装置和状态反馈优先使用可控的 SVG/Canvas/CSS。**三维空间页**：`visualProtagonist` 须指向 WebGL 场景内的可观察实体（网格、向量、分子等），不得写成「CSS 立体卡片」或 `preserve-3d` 层叠；`teachingVisualization` 须支持旋转/缩放/选中等 3D 操作，技术栈写 `THREE.js`（见 `content-guide.md`「三维可视化」）。图片生成工具返回的 OSS/HTTPS URL 仍是外部运行依赖，不能视为内联素材。用户要求“自包含”“不依赖外部资源”或同义约束时，素材策略必须写成 `SELF_DRAWN_ONLY`，不调用图片搜索/`generate_image`，所有主图、环境层、箭头、热点和打印态都用内联 SVG、Canvas 或 CSS。自包含扫描只针对资源引用（`src`/`href`/`url()`/`assets[].url` 等），**不**把 SVG/XML 命名空间 URI（如 `http://www.w3.org/2000/svg`）算作外部依赖。每个素材都要写明用途、是否核心、失败降级与语义关系，禁止用多张装饰图掩盖教学主角缺失。

## 8. 响应策略

桌面端先保证视觉主角、核心控件和当前反馈形成一个连续操作区。小视口不是把桌面页等比缩小：

- 优先保留当前任务、视觉主角的关键部分、主操作和当前反馈；
- 将概念补充、规则长文和次要统计折叠或移到后续状态；
- 标题使用 `clamp()`、短副标题或分层换行，不能长期占据首屏；
- 图示在小屏可简化标签、改为聚焦视图或上下布局，但不得丢失关系；
- 核心 SVG/Canvas/CSS 主图必须保留完整语义边界与关系路径：优先使用完整 `viewBox` 等比缩放或布局重排，不用固定像素画布、`cover` 或裁切容器丢失主图一侧；
- 控件保持可触达，反馈出现后不遮挡下一动作；
- 不用 `overflow:hidden`、极小字号或隐藏滚动条掩盖失败。

学科链路的字号和按钮值是桌面基线；当固定值会挤压核心任务时，应使用其允许的 `clamp()`、分步、折叠或重排。响应完整性优先于机械保持空白和装饰。

## 9. 写入 artifact-spec

最低结构：

```json
"experienceDesign": {
  "archetype": "simulation|game-challenge|visual-explanation|guided-practice|interactive-poster|print-material",
  "thesis": "学生通过什么动作，借助什么视觉主角，达到什么理解或完成状态",
  "visualProtagonist": "唯一主角及其教学作用",
  "stageComposition": "主角、关系层、环境层、就近标注和支持控件如何组成连续舞台",
  "teachingVisualization": [
    {"relation":"教学关系","encoding":"视觉编码","binding":"交互与反馈绑定"}
  ],
  "artDirection": "受众、学科隐喻、形状语言与空间隐喻",
  "stateStoryboard": ["initial","engaged","feedback","completion","reset","mobile"],
  "assetPlan": "核心素材、非核心素材与降级策略",
  "responsivePolicy": "桌面与小视口的保留、折叠和重排原则"
}
```

## 10. 生成前验收

```text
□ 体验命题包含动作、视觉主角和可验证结果
□ 只有一个主原型，首屏重心与原型一致
□ 至少一个教学关系完成“关系—视觉编码—状态绑定”
□ 视觉主角不是通用卡片或装饰图
□ 主角占据主体区域的大部分注意力，支持卡片没有把它切碎
□ 舞台具有与主题绑定的空间/材质隐喻及清楚的前中后层次
□ initial / engaged / feedback / completion / reset / mobile 均有方案
□ 艺术方向能约束形状、线条、空间和动效，不只是风格形容词
□ 图片和代码复杂度都服务教学关系，图片数量不作为目标
□ 小视口保留核心任务、主角、操作和反馈
```
